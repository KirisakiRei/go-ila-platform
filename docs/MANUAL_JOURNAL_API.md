# Manual journal API contract

Standalone, owner-only manual journal. Parent mounts `handler.NewManualJournalHandler(service.NewManualJournalService(repository.NewManualJournalRepository(db), privateUploadDir)).Register(authenticatedGroup)`; group should be `/api/v1`. No broker/runner integration. Parent migrates `model.ManualJournalAccount`, `ManualJournalCapital`, `ManualJournalEntry`, `ManualJournalScreenshot`, **`ManualJournalImportToken`** (new persistent preview/consumption table `manual_journal_import_tokens`, required before enabling CSV preview/confirm). Private upload directory must NOT be publicly served (use a dedicated subdirectory of configured bug upload root). Existing error middleware and authenticated CurrentUserID required.

## Routes
Prefix `/manual-journal`:
- GET/POST `/accounts`; GET/PUT/DELETE `/accounts/:id`. DELETE archives (never removes trades); PUT full replacement including `archived` to restore.
- GET/POST `/capital`; GET/PUT/DELETE `/capital/:id`.
- GET/POST `/entries`; GET/PUT/DELETE `/entries/:id`.
- GET `/stats`; GET `/insights` (deterministic rules, not AI).
- POST `/entries/:id/screenshots` multipart `file` (max 5 MiB PNG/JPEG/WebP/GIF); GET `/entries/:id/screenshots`; GET/DELETE `/entries/:id/screenshots/:sid`. GET file is private owner-authorized, no public URL.
- POST `/import/preview`: JSON `{ "csv": "..." }`; validates all rows, persists an owner-scoped SHA-256-bound token, returns `{rows,count,token,expires_at}`. No trades inserted. Token lifetime 15 minutes.
- POST `/import/confirm`: JSON `{ "csv": "...", "token": "UUID from preview" }`; exact original CSV bytes required. Returns `{count}`. Confirm reparses/revalidates and atomically consumes token + inserts all rows. Repeat/concurrent confirm of the same token never duplicates entries: consumed/expired token is `409 CONFLICT`, another user's/unknown token `404 NOT_FOUND`, changed payload `400 BAD_REQUEST` (invalid entry/account data may fail validation first). No token is consumed on failure. Frontend must retain `rows` for display AND `token` from preview; send that token with unchanged CSV, disable repeat confirmation after success; rerun preview when CSV changes/expires. Existing `{csv}`-only confirm callers must be updated by parent. Max 1 MiB / 500 rows.
- GET `/export`: CSV using the same entry filters, **max 500 rows AND 1 MiB of final encoded CSV bytes** (including header, quoting and formula escaping). Exceeding either returns `400 BAD_REQUEST` before any download body is sent; narrow filters. No silent truncation. These limits match importer limits; stats/insights retain the separate 10,000-row bound. Parent/frontend: show export limit as “500 rows / 1 MiB; narrow filters if exceeded” alongside the export action.

Existing httpx envelope: `{success,message,data,meta?}`; errors via apperror. Lists have `meta:{current_page,per_page,total_items,total_pages}`. All IDs UUID strings. Foreign-owned IDs return 404, not authorization leaks.

## Payloads
Money and prices are **decimal JSON strings**, never JSON numbers. Money max 4 fractional digits, prices/size max 8, absolute value <= 1,000,000,000. Null money is distinct from zero. Values never inferred from prices (instruments have differing contract multipliers). Net PNL is user-entered realized net amount including fees. All API timestamps RFC3339 with explicit offset; local naive timestamps rejected. Date filters and daily grouping use Asia/Jakarta (WIB), not client timezone.

Account input: `{name,broker,currency,initial_capital,initial_date,notes,archived,checklist}`; currency exactly 3 uppercase letters, initial_date `YYYY-MM-DD`, checklist array of strings (max 30). Broker is descriptive text only; no broker account relation. Initial capital nonnegative. Currency immutable after creation (create another account to change currency). Checklist edits do not mutate existing entry snapshots. Archived accounts remain readable but reject capital/entry/screenshot mutations until restored.

Capital input: `{account_id,kind,amount,date,notes}`; kind `deposit|withdrawal`, amount strictly positive, date `YYYY-MM-DD`. Capital movements are separate from realized PNL and never counted as wins/losses.

Entry input: `{account_id,status,asset,side,opened_at,closed_at,entry_price,stop_loss,take_profit,exit_price,size,size_unit,net_pnl,risk_amount,capital_snapshot,setup,tags,emotions,mistakes,session,checklist,notes,tradingview_urls}`.
- status `draft|open|closed`; side `long|short` (draft may omit asset/side).
- timestamps and prices optional/null for drafts; open requires asset, side, opened_at, entry_price, size and size_unit; closed additionally requires closed_at and net_pnl (zero allowed). Exit price remains optional. close cannot precede open; nonclosed records cannot carry realized PNL/close time.
- risk_amount and capital_snapshot nullable, nonnegative. `capital_snapshot` is caller-supplied historical capital, not auto-calculated.
- tags/emotions/mistakes and TradingView URLs string arrays (max 30 each); setup/session text. URLs HTTPS tradingview.com or its subdomains only.
- checklist input `[{label:"...",checked:true}]`; create snapshots current account checklist labels and applies checked values (unknown labels rejected). Updates retain snapshot labels independent of current account template.
- response adds id/user_id/created_at/updated_at; screenshot metadata separate endpoint. PUT is full replacement, not merge patch. Entry account cannot change on update.

## Queries
All lists: `page=1&per_page=20` (max 100), `search` (max 100). Accounts additionally `archived=true|false` (omitted includes both). Account responses (create/update/get/list) add `current_realized_balance: string|null`, `balance_complete: boolean`, `unknown_closed_pnl: integer`. These are additive response fields; parent frontend may type balance as optional for compatibility. Balance is initial_capital + all nondeleted deposits - withdrawals + all nondeleted closed net_pnl for that owner/account, in account currency, exact-decimal aggregation with 4-place output. No list/page/date filters or initial_date cutoff apply to balance: initial capital must be a baseline excluding every separately recorded movement/trade to avoid double-counting. Draft/open trades and unrealized PNL excluded. Archived accounts still return their balance. If any closed entry has NULL net_pnl, balance is NULL, balance_complete=false, unknown_closed_pnl counts those entries; unknown is never treated as zero. Invalid persisted decimal/storage errors fail explicitly. This is journal-recorded realized balance, not broker equity, live mark-to-market, or verification of missing unrecorded trades. No model migration needed for these computed response fields. Entries/capital: `account_id`, `from`, `to` inclusive WIB dates. Entries: `status`, `asset`, `side`, `tag`, **`emotion`**, **`mistake`**, `session`, `setup`. Tag/emotion/mistake are singular exact labels, max 100 bytes; all supplied filters combine with AND. JSON string encoding + parameterized escaped LIKE matches the serialized list label (SQL wildcard characters are literal). Entry list, stats, deterministic insights and export share these filters. Parent/frontend: add emotion/mistake query fields to JournalFilters and forward them with all report/export requests; no AI payload change. Entry dates use closed_at for closed entries, opened_at otherwise, created_at for drafts without an open time. Search is literal substring (SQL wildcard characters escaped), across asset/notes/setup for entries, name/broker/notes for accounts, notes for capital. Stats, insights, export reuse entry filters without pagination.

## Statistics and insights
Only closed entries with non-null net_pnl are realized. Whole filtered set, not current page. Stats/insights capped at 10,000 rows with explicit validation error, never partial/truncated results. CSV export has a separate matching import/export cap of 500 rows / 1 MiB. Monetary stats refuse mixed account currencies; select an account or accounts with a single currency. Returned stats: currency, trades, wins, losses, breakeven, win_rate (100 * wins/(wins+losses), excluding breakeven, `0.0000` when no wins/losses), profit_factor (null without losses), average_win, average_loss (positive magnitude), net_pnl, max_drawdown (absolute peak-to-trough cumulative realized PNL), curve (chronological trade id/date/pnl/cumulative/drawdown), calendar (WIB daily pnl/count), breakdowns by asset/setup/session/tag/emotion/mistake/side. Multi-label breakdowns overlap, so sums need not equal overall total. Empty reports return zero amounts and empty arrays/maps. Initial capital and deposits/withdrawals excluded from PNL curve/drawdown; no fabricated percentage return for unknown capital. These reports are cumulative realized PNL, NOT account equity/balance or cashflow-adjusted returns. Initial capital/movements contribute to the separate account current_realized_balance response only, not PNL reports; capital_snapshot is optional user-supplied historical data, not an authoritative computed balance. Archived accounts/trades remain included unless filtered by account; archive only prevents mutations and does not erase realized history. Ratios rounded to 4 decimals; monetary output fixed 4 decimals.

Insights: deterministic low-sample warning (<20 closed trades), negative expectancy, repeated mistake counts, losing setup/session groups with >=3 trades, plus `losing_streak` when the latest chronological realized trades end with at least 3 consecutive negative PNLs (`count` = streak length). Chronology is closed_at ASC then UUID ASC for ties, using the whole filtered set; zero PNL/breakeven and positive PNL both stop the streak. Open/draft and unknown PNL do not contribute. The streak describes the selected filtered series, not necessarily all account history. Fixed message contains no raw labels. No AI/network dependency or changes to AI requests.

CSV exact header (export round-trips into import):
`account_id,status,asset,side,opened_at,closed_at,entry_price,stop_loss,take_profit,exit_price,size,size_unit,net_pnl,risk_amount,capital_snapshot,setup,tags,emotions,mistakes,session,checklist,notes,tradingview_urls`
Array/checklist cells contain JSON. Nullable cells empty. Preview returns `{rows:[validated entry payloads],count:N,token:"UUID",expires_at:"RFC3339 UTC"}`. Confirm returns `{count:N}`. CSV errors identify the row; no invalid row is silently skipped. Exports prefix formula-leading text (=,+,-,@, tab, CR, LF, including after whitespace) with apostrophe; import removes only the escape recognized by this exporter. IDs/timestamps are not derived from CSV. New entry UUIDs on successful import; preview token is persistently single-use across processes/restarts, consumed in the same database transaction as entry insertion. Replays return 409 without insertion. A deliberate NEW preview issues a new token and can intentionally import identical CSV again (no global content deduplication). Import preserves each CSV checklist as the historical snapshot, including order and checked values, independently of the current account template (also if the template changes between preview and confirm). Snapshot validation: max 30 items, unique nonblank labels, max 200 UTF-8 bytes per label, no NUL, boolean checked values; an empty snapshot remains empty. Standard entry create still snapshots current account labels; standard update retains existing snapshot labels. Account ownership/archive checks and all remaining trade validation still apply; archived accounts must be restored before import. CSV is an entry transfer, not a full account/capital/screenshot backup. Successful nonempty exports under the limits can be previewed/confirmed without removing historical checklist labels. JSON request body transport allows CSV escaping expansion up to six bytes per CSV byte plus 1 KiB envelope; decoded CSV remains limited to 1 MiB.
